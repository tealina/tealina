# AGENTS.md

Instructions for anyone—human or agent—changing this repository. `CLAUDE.md` points here; keep
this file as the single copy.

## What this repository is

A pnpm monorepo for **tealina**: a CLI, a zero-dependency runtime, and a set of type packages
that turn "directory tree + handler type annotation" into routes, client types, and API docs.

| Package | Role |
|---|---|
| `packages/tealina` | CLI: `create` adds endpoints, `delete` removes them, `align` regenerates barrels, `gdoc` writes the API document, `gtype` generates pure types |
| `packages/tealina-server` | Runtime. Exactly two exports: `loadAPIs`, `transformToRouteOptions` |
| `packages/tealina-client` | Fetch/axios RPC clients for the browser |
| `packages/utility-types` | Type-only conditional-type toolbox |
| `packages/tealina-doc-types` | Types of the API document |
| `packages/tealina-doc-ui`, `tealina-doc-ui-src` | Documentation site UI and its source |
| `packages/create-tealina` | Scaffold. One `create` entry; ships `template/` — three backend packages (`core`, `api-v1`, `server`) and an optional `web` |

Architecture is described in [docs/architecture.md](./docs/architecture.md). Read
[docs/architecture-notes.md](./docs/architecture-notes.md) before changing anything in the
contract layer; it lists the couplings that fail silently. Dated background lives in
[docs/history.md](./docs/history.md) and is not required for a change.

## Toolchain

This project uses **Vite+**, which wraps Vite/Rolldown/Vitest/tsdown/Oxlint/Oxfmt in one `vp`
CLI. `vp` is not Vite: `vp dev` and `vp build` invoke Vite, and `vp run <name>` runs a
`package.json` script or a `vite.config.ts` task. Built-in commands win over scripts, so check
`package.json` first.

```bash
vp install                 # after pulling; refreshes the lockfile
vp check                   # format + lint + type check
vp test                    # all test projects
vp run -r build            # build every package
pnpm verify                # build + check + test, in that order
vp toolchain [tool]        # versions in the active Vite+ release
vp why <package>           # dependency graph
vp env doctor              # when setup/runtime/package-manager behavior looks wrong
```

Run tests through `vp test` or the package script, not bare `npx vitest run`:
`create-tealina` needs `--testTimeout=0`, which the configured script supplies. End-to-end tests
are skipped locally unless `TEALINA_E2E=1`; on CI they run automatically because GitHub Actions
sets `CI`.

**Node ≥ 22** is the floor. `vite-plus-core`'s tsdown uses `Promise.withResolvers`, which Node 20
does not have, so a Node 20 build fails at the first step. `engines.node`, each package's
`target: 'node22'`, and `@types/node` describe that floor; `.nvmrc` and CI run the default
**Node 24**. The package manager is pinned by `packageManager: pnpm@12.5.1`, and `engines.pnpm`
requires the 12.x line.

## Hard constraints

1. **Generated files are not source.** Every file written by `align` starts with
   `// @generated by tealina — do not edit.` (`kGeneratedHeader` in
   `packages/tealina/src/utils/codeGen.ts`). That covers `src/api/**/index.*` and the fallback
   `types/api.d.ts`. Change the generator, then rerun `align`; never edit the output.
2. **All writes go through `Snapshot`.** In `packages/tealina`, files are written only via
   `utils/effectFiles.ts`. Keep generation idempotent: rerunning must produce no write when
   nothing changed (`changedOnly`). New generation paths must also work under `--check`, which
   uses the same snapshots and stops before writing.
3. **The template is data, not this repo's source.** `packages/create-tealina/template/**` is
   shipped into user projects and is excluded from this repo's type check and lint (its imports
   only resolve inside a scaffold). Changes must land in **all three framework trees per package**
   (express, fastify, koa) where the file exists in each; `test/template-parity.test.ts` enforces
   the layout and `test/template-manifest.test.ts` enforces the manifest.
4. **`src/template-manifest.ts` is the list of shipped files.** A file added under
   `template/core/`, `template/api-v1/`, `template/server/` or `template/web/` but not named
   there never ships. The three backend packages each get their own destination root —
   `backend/core`, `backend/api-v1`, `backend/server`. `template/root/` is the exception: it is
   copied wholesale, so anything placed there ships as-is. `template/integration/` is the
   other: it holds one file, `INTEGRATION.md`, copied to the project root only when
   `--integrate` is passed; nothing else there ships.
5. **The contract layer is `types/handler.d.ts` + one `types/alias.d.ts` per framework.** Change
   them only when you intend to change the convention for every handler in every generated
   project. `alias.d.ts` is the only framework seam. Express's alias repeats its call signature
   on purpose: a `.js` handler annotated with a JSDoc `@type`, kept while a project migrates to
   TypeScript, is rejected by a single signature. Do not "simplify" it away.
6. **Artifact names are fixed; `apiDir` is configuration.** `tealina.config` supplies `apiDir`
   and `apiBaseURL`, and the CLI commands take no directory argument. The type file is always
   `types/api.d.ts`, the document `docs/api.json`, the package export `./api`. Renaming the api
   directory changes route discovery and the handlers' own imports, not a public name.
   `apiBaseURL` is still written separately in each router's mount prefix and the web client's
   `base` — update them together.
7. **`__@ResponseFlagSymbol` is a string convention.** `utility-types` declares the symbol;
   `packages/tealina/src/utils/parseDeclarationFile.js` matches it with a regex. Renaming it will
   compile and silently degrade document generation.
8. **User-facing changes need a changeset.** Public API or CLI behavior changes go in
   `.changeset/`. The scaffold's `create-tealina` major version is intentional; do not "fix" it.

## Working on the scaffold

```bash
node packages/create-tealina/dist/index.mjs          # run the built scaffold
pnpm -F create-tealina test                          # manifest/parity/contract tests
TEALINA_E2E=1 pnpm -F create-tealina test            # real install + server + request
```

The scaffold has one entry point and one template:

- `create` builds a new monorepo: three backend packages (`core`, `api-v1`, `server`), the
  contract layer, the docs, and optionally a Vite frontend (`--web`). `--template` makes it
  non-interactive. It writes files only: installing and generating the document are the
  project's first commands, printed at the end.
- The backend packages depend on each other in one direction: `core → api-v1 → server`.
  `pnpm -r build` is topological, so a package that imports a sibling builds after it.

When changing a template file, ask which frameworks carry it. A project that still keeps
`.js` handlers does not have a template of its own: it enables `allowJs`/`checkJs` and sets
`sourceExt: '.js'` in `tealina.config.ts`, which the generator honours by emitting a JSDoc
stub. The recipe is in `packages/create-tealina/README.md`.

## Documentation

- `docs/` is also a VitePress site (Chinese, user-facing). It is an **independent pnpm
  project** with its own `package.json`, `pnpm-workspace.yaml` and lockfile; do not add it to
  the root workspace. Use `pnpm docs:dev` / `pnpm docs:build`. Root `vp install` does not
  install it, and `docs/**` is excluded from root lint/type check.
- `docs/architecture.md` — current architecture, by subsystem.
- `docs/architecture-notes.md` — judgement: couplings, what not to change casually, what CI
  does not cover.
- `docs/history.md` — dated decisions, only when you need the "why".
- `packages/create-tealina/template/common/api-v1/AGENTS.md` — what a generated project tells
  its own agent; keep it consistent with the CLI.
