# Tealina Roasters

A small specialty-coffee shop used as a realistic demo of the tealina toolchain: a typed
three-package API, generated documentation, and a React storefront styled with UnoCSS whose
client types are read straight off the server's handlers.

Nothing connects to a database. The api keeps its users, products, orders and comments in
memory, so `pnpm dev` works with no setup and restarting the server returns the shop to
its seed state.

## Run it

```bash
cd playground/tealina-shop
pnpm install
pnpm dev
```

| What | Where |
| --- | --- |
| Storefront | http://localhost:5173 |
| API | http://localhost:8000/api/v1 |
| Documentation and playground | http://localhost:8000/api-doc/index.html |

`pnpm dev` builds `core` and `api-v1`, then starts the api, the server and the web dev
server in parallel. The storefront's proxy forwards `/api/v1` and `/api-doc` to port 8000;
if you change `PORT` in `backend/server/.env`, change `packages/web/vite.config.ts` too.

## Things to try

**Storefront**

- Search “grinder”, pick a category, change the sort, and page through the shelf. All four
  are applied by the server; the page just forwards its controls as the query.
- Open a product to read its reviews and post one while signed in.
- Add a few bags to the cart, change quantities, then reload the page — the cart is kept in
  `localStorage`.
- Check out signed out, then sign in from the dialog and place the order. Stock is checked
  and decremented in the same request; the order gets a `TS-YYYY-NNNN` number.

**Back office** (sign in as the admin)

- The dashboard reads `GET /stats/overview`: revenue, order counts, low stock and recent
  orders — admin only.
- Move an order through `PENDING → PAID → SHIPPED → DELIVERED`, or cancel it while it is
  still pending or paid. Cancelling returns the units to stock.
- Restock a low-stock item with `+10`, or edit its stock in the catalog table.
- Add a product. The form posts the body generated by `gtype` from the Prisma schema; the
  slug is derived from the name.
- Delete a product that has never been ordered, then try one that has — the second answers
  `409` with an explanation.
- Export the order list as CSV: the endpoint declares a `Blob` for the client and
  `Content-Disposition` headers for the document.

**Live activity**

- Press **Start feed** on the dashboard. It opens `GET /feed/activity` with
  `EventSource`, replays the last events, then streams new ones for a few seconds.
- With the feed running, place an order from another tab (or the documentation playground)
  and the event arrives in the list.

**Documentation**

- Open `/api-doc/index.html` and browse one version. Every route shows the types and JSDoc
  written in its handler file.
- Open a route's playground. The products query and the checkout body ship named examples;
  the activity endpoint streams events into the response panel; the export endpoint shows
  the CSV headers.

## Endpoint map

`src/api/<method>/<path>.ts` is the route. `openApi` handlers are public; `authedApi`
handlers require a bearer token, and an admin check lives inside the handler where it
belongs to the data.

| Method and path | Access | What it does |
| --- | --- | --- |
| `GET /health` | public | readiness |
| `GET /categories` | public | filter row |
| `GET /products` | public | search, filter, sort, page |
| `GET /products/:id` | public | one product with rating |
| `GET /products/:id/comments` | public | reviews |
| `POST /auth/login` | public | issue a demo token |
| `POST /auth/register` | public | create a customer account |
| `GET /feed/activity` | public | server-sent events |
| `GET /me` | authed | the current account |
| `GET /orders` | authed | own orders; every order for an admin |
| `GET /orders/:id` | authed | own order, or any as admin |
| `POST /orders` | authed | check out |
| `POST /products/:id/comments` | authed | post a review |
| `GET /orders/export` | admin | orders as a CSV download |
| `GET /stats/overview` | admin | dashboard numbers |
| `POST /products` | admin | create a product |
| `PATCH /products/:id` | admin | edit a product |
| `DELETE /products/:id` | admin | delete an un-ordered product |
| `PATCH /orders/:id/status` | admin | advance or cancel an order |

Errors all share one body: `{ code, message }`, where `code` is `VALIDATION_ERROR`,
`NOT_FOUND`, `CONFLICT`, `FORBIDDEN` or `UNAUTHORIZED`. The web client raises it as
`ApiError`.

## How the pieces fit

**Route table.** Every file under `backend/api-v1/src/api/` is an endpoint; its directory
is the method and its path is the url. `[id].ts` becomes `:id`. The `index.ts` files are
generated:

```bash
pnpm -F api-v1 align          # regenerate the route barrels
pnpm -F api-v1 align --check  # verify they are current
```

**Contract.** A handler's annotation is the single source of truth for the router, the
document and the frontend:

```ts
type ApiType = AuthedHandler<{ body: CheckoutPayload }, WithStatusCode<201, OrderView>>
const handler: ApiType = async (req, res) => { /* ... */ }
export default authedApi(handler)
```

`AuthedHandler` on `authedApi`, `OpenHandler` on `openApi`; express's types reject the
mismatch. `backend/core/src/access/verifyToken.ts` validates the shop's signed token and
puts `userId` and `role` on `res.locals`.

**Types from the schema.** `backend/api-v1/prisma/schema.prisma` is the data model;
`gtype` turns it into `types/pure.d.ts`, and `tealina.config.ts` maps `DateTime` to
`string` for the wire:

```bash
pnpm -F api-v1 gtype
```

**More than JSON.** Two endpoints show the contract carrying more than a JSON body:
`GET /orders/export` uses `MultiTarget` to say “a file for the browser, headers for the
docs”, and `GET /feed/activity` says “the server owns the socket, the client sees an
`AsyncGenerator`”.

**Documentation.** `gdoc` derives `docs/api.json` from the same annotations and JSDoc. The
custom output in `tealina.config.ts` also converts that document into
`docs/openapi.json` (OpenAPI 3.1), ready for Swagger UI, Postman or code generation:

```bash
pnpm -F api-v1 gdoc
pnpm -F api-v1 gdoc --check
```

**The frontend does not restate the API.** `packages/web/src/api/client.ts` creates the
typed client from `ApiTypesForClient`, and `packages/web/src/types.ts` derives every shape
it uses:

```ts
export type ProductView = TakeResponse<'get', 'products/:id'>
export type CheckoutPayload = TakeBody<'post', 'orders'>
```

The UI is React 19. `packages/web/uno.config.ts` holds the theme, shortcuts and the
light/dark CSS variables that UnoCSS compiles into `uno.css`.

Rename a field in a handler and `pnpm -F web build` stops compiling. That is the feature
on display.

## Checks and commands

| Command | What it does |
| --- | --- |
| `pnpm check` | format, lint and type-check the whole project (Vite+) |
| `pnpm fmt` / `pnpm lint` | one at a time |
| `pnpm build` | build every package and the bundle |
| `pnpm -F api-v1 create <method> <path>` | create a handler stub |
| `pnpm -F api-v1 delete <method> <path>` | remove a handler and its barrel entry |
| `pnpm -F api-v1 align` | regenerate the route barrels |
| `pnpm -F api-v1 gdoc` | regenerate the API document |
| `pnpm -F api-v1 gtype` | regenerate `types/pure.d.ts` from the Prisma schema |
| `pnpm -F web dev` | storefront only, http://localhost:5173 |

Generated files — `src/api/**/index.*`, `docs/api.json`, `docs/openapi.json`,
`types/pure.d.ts` — belong to those commands; edit the handler or the schema instead.

The token secret is `AUTH_SECRET` with a demo fallback. Orders, accounts and reviews live
in memory: `Ctrl+C` and `pnpm dev` again gives you a fresh shop.
