# tealina

The tealina CLI. It turns handler files into routes, a handler annotation into an API
document, and a Prisma schema into plain TypeScript types — so the route list, the
documentation and the client types all come from one source.

| Command | What it does |
| --- | --- |
| `create [route]` | Writes a handler stub and updates the route barrels |
| `delete <route>` | Deletes a handler and updates the route barrels |
| `align` | Rebuilds every generated barrel from the files on disk |
| `gdoc` | Generates the API document from `types/api.d.ts` |
| `gtype` | Generates types from a Prisma schema |

```bash
npm install -D tealina
```

The CLI needs **Node ≥ 22** and TypeScript `>=5.6.2 <7` (it drives the Compiler API to
read declaration files). TypeScript 7 is the Go-native rewrite and does not expose that
API yet — the current release, 7.0.2, is therefore not supported.

## Setup

Every command reads one config file — `tealina.config.ts`, or a `.js` / `.mjs` file with
that name:

```ts
// tealina.config.ts
import { defineConfig } from 'tealina'

export default defineConfig({
  apiDir: 'src/api',
  apiBaseURL: '/api/v1',
  typesDir: 'types',
})
```

`apiDir` is the only input to route discovery. `apiBaseURL` is the prefix those routes
answer under; the CLI does not infer it from the directory name. Keep the package's
scripts argument-free:

```json
{
  "scripts": {
    "create": "tealina create",
    "align": "tealina align",
    "gdoc": "tealina gdoc"
  }
}
```

Generated artifacts have fixed names — `types/api.d.ts`, `docs/api.json` and the
package's `exports["./api"]` entry — so moving or renaming `apiDir` changes no public
name.

## The route convention

The first directory level under `apiDir` is an HTTP method; every file below it is an
endpoint. The path is the file path, with `[id]` spelling a route parameter:

```
src/api/
  index.ts                 generated
  get/
    index.ts               generated
    health.ts              GET /health
    user/
      [id].ts              GET /user/:id
  post/
    index.ts               generated
    user/
      login.ts             POST /user/login
```

The generated barrels look like this:

```ts
// src/api/get/index.ts
// @generated by tealina — do not edit.
// Rebuild it with: tealina align

export default {
  health: import('./health.js'),
  'user/:id': import('./user/[id].js'),
}
```

```ts
// src/api/index.ts
export default {
  get: import('./get/index.js'),
  post: import('./post/index.js'),
}
```

Never edit an `index.*` file under `apiDir`: it is derived output. Add, rename or delete
handlers, then run `align`.

`align` also writes a fallback `types/api.d.ts` when the project has none. That file
exports `ApiTypesForDoc` and `ApiTypesForClient`; `gdoc` reads the first, and a frontend
imports the second through the package's `exports["./api"]`.

## Commands

### `create`

```bash
tealina create post/user      # src/api/post/user.ts
tealina create user/login     # the missing method defaults to post
tealina create post/user/:id  # [id] spells the parameter segment
tealina create -m -i ./prisma/schema.prisma -t c  # with a template aliased "c"
```

Options:

| Option | Meaning |
| --- | --- |
| `-m, --model` | Create one endpoint per model in the Prisma schema |
| `-i, --input <path>` | Prisma schema path (default `./prisma/schema.prisma`) |
| `-t, --template-alias <alias>` | Select handler templates by their alias |
| `--with-test` | Also generate the integration test file |
| `--tp, --tsconfig-path <path>` | tsconfig used to resolve handler types |

Batch mode (`--model`) requires both `-i` and `-t`. Without `-t`, `create` uses the
fallback template whose alias is `*`.

Route segments written as `:id` are converted to the `[id]` file spelling, so
`tealina create post/user/:id` and `tealina create post/user/[id]` both write
`src/api/post/user/[id].ts`.

### `delete`

```bash
tealina delete post/user/login
tealina delete post/user/login --with-test
```

Removes the handler and rewrites the barrels. The same `--tp / --tsconfig-path` option is
available.

### `align`

Rebuilds every generated `index.*` and the fallback type file from what is actually on
disk. This is the command to run after any manual file change.

```bash
tealina align
tealina align --check
tealina align --check --json
```

`--check` computes the same result and writes nothing; it exits `1` when generated files
are out of date. `--json` prints one object on stdout:

```json
{ "ok": false, "changed": [{ "action": "update", "file": "src/api/get/index.ts" }] }
```

Patterns in `exclude` are relative to `apiDir` and matched as posix paths. They keep a
file or directory out of the route tree:

```ts
export default defineConfig({
  apiDir: 'src/api',
  apiBaseURL: '/api/v1',
  typesDir: 'types',
  exclude: ['_shared/**', '**/*.test.ts'],
})
```

### `gdoc`

Reads `types/api.d.ts`, follows the handler imports, and writes `docs/api.json`. The CLI
reads the **first exported type declaration** in that file, so `ApiTypesForDoc` has to
stay its first export; `ApiTypesForClient` is the second.

```bash
tealina gdoc
tealina gdoc -o docs
tealina gdoc --check
```

It accepts the same `--check` and `--json` flags as `align`, plus `--tp` and
`-o / --output` for the output directory.

The document follows the `@tealina/doc-types` model. A custom output receives the whole
`ApiDoc` and the configured base URL:

```ts
import { convertToOpenApiJson } from 'tealina'

export default defineConfig({
  // ...
  gdoc: {
    customOutputs: [
      (apiDoc, { baseURL }) => ({
        content: JSON.stringify(convertToOpenApiJson(apiDoc, baseURL)),
        filePath: 'docs/openapi.json',
      }),
    ],
  },
})
```

With `customOutputs` set, the default `docs/api.json` output is replaced. Add
`keepOriginalOutput: true` to write both.

### `gtype`

Reads a Prisma schema and writes pure TypeScript types. Relation fields are omitted, so
the output composes without dragging the whole model graph along.

```bash
tealina gtype
tealina gtype -i ./prisma/schema.prisma -o types/pure.d.ts -n Pure
```

If `--input` is missing, the CLI reads `schema` from `prisma.config.ts` when that file
exists, and otherwise uses `./prisma/schema.prisma`.

Defaults: output `types/pure.d.ts`, namespace `Pure`. The `gtype` block accepts:

```ts
export default defineConfig({
  // ...
  gtype: {
    output: 'types/pure.d.ts',
    namespace: 'Pure',
    // Only affects the generated CreateInput / UpdateInput types.
    typeRemap: type => (type === 'DateTime' ? 'number' : null),
  },
})
```

`gtype.overwrite` can make selected mutation properties optional, rewrite their types, or
drop them. Entries match a block and mutation kind:

```ts
overwrite: {
  isOptional: [
    {
      blockName: '*',
      keyword: '*',
      kind: 'UpdateInput',
      predicate: prop => prop.name === 'id',
    },
  ],
}
```

The callback shapes are exported as `Overwrite`, `MatchForOptionalCheck`,
`MatchForTypeTransform` and `MatchForExcludeProp`.

## Configuration reference

```ts
interface TealinaConfig {
  apiDir: string
  apiBaseURL: string
  typesDir: string
  exclude?: string[]
  handlerImport?: string
  suffix?: string
  sourceExt?: string
  testDir?: string
  template?: TemplateConfig
  gtype?: GtypeConfig
  gdoc?: GdocConfig
}
```

| Option | Default | Purpose |
| --- | --- | --- |
| `apiDir` | — (required) | Directory whose files are routes |
| `apiBaseURL` | — (required) | Public URL prefix the routes answer under |
| `typesDir` | — (required) | Where `api.d.ts` lives |
| `exclude` | `[]` | Globs, relative to `apiDir`, that are not routes |
| `handlerImport` | `./handler${suffix}` | Module the fallback type file imports handler types from |
| `suffix` | `.js` | Extension written in generated `import` statements |
| `sourceExt` | `.ts` | Extension of generated files; `.js` for a JavaScript project |
| `testDir` | — | Where `--with-test` writes integration tests |
| `template` | — | Custom handler and test generators |
| `gtype` | — | Prisma type generation options |
| `gdoc` | — | Custom document outputs |

`suffix` and `sourceExt` are separate on purpose: a NodeNext TypeScript project imports
`'./health.js'` while the file on disk is `health.ts`.

Global options are `--config-path <path>` (default `./tealina.config.ts`) and
`--verbose`, which prints the stack when a command throws.

## Custom templates

`template.handlers` replaces the built-in handler stub. Each entry has an alias, an
optional template name (also the generated filename) and an optional method:

```ts
import {
  defineApiTemplates,
  defineConfig,
  makeTestHelperTemplate,
  makeTestSuiteTemplate,
} from 'tealina'

const handlers = defineApiTemplates([
  {
    alias: 'c',
    name: 'create',
    method: 'post',
    generateFn: ctx => `// ${ctx.method} ${ctx.dir}/${ctx.filename}`,
  },
  { alias: '*', generateFn: () => 'export default () => {}' },
])

export default defineConfig({
  apiDir: 'src/api',
  apiBaseURL: '/api/v1',
  typesDir: 'types',
  template: {
    handlers,
    test: {
      genSuite: makeTestSuiteTemplate(ctx => `// test ${ctx.method} ${ctx.route}`),
      genHelper: makeTestHelperTemplate(ctx => `// ${ctx.apiDirName}`),
    },
  },
})
```

`ctx.sourceExt` tells a generator whether the project writes `.ts` or `.js`;
`ctx.fileDir` is the directory the handler will land in. The alias `*` is the fallback
used when no method/name or alias entry matches.

## Programmatic exports

| Export | Purpose |
| --- | --- |
| `defineConfig` | Identity helper for the config object |
| `defineApiTemplates` | Identity helper for a handler template list |
| `makeTemplate` | Identity helper for one handler generator |
| `makeTestSuiteTemplate` / `makeTestHelperTemplate` | Identity helpers for test generators |
| `convertToOpenApiJson` | Convert an `ApiDoc` to OpenAPI 3.1 |
| `tealina/utility-types` | Type-only re-export of `@tealina/utility-types` |

`OpenAPIV3` and `OpenAPIV3_1` from `openapi-types` are re-exported as types.
