# create-tealina

## 3.0.0

### Major Changes

- 0f3fd92: Replace the full-kit scaffold with the minimal one

  `create-tealina` now generates the minimal scaffold: no database layer, no Prisma or SQLite,
  no `shared-types` package, no React frontend, no bun fork — node only. What remains is the
  API server, its contract layer and its documentation generator.

  The backend is three packages with one job each: `backend/core` holds the contract layer and
  the access module, `backend/api-v1` holds one API version's route tree, its document and the
  code that mounts them, and `backend/server` is the host. A second version is a new package
  (`backend/api-v2`), and the dependency direction is `core → api-v1 → server`.

  `--web` adds a minimal Vite frontend in `packages/web` that reads the contract through
  `api-v1/api`. A `template-manifest.ts` names every file the scaffold writes. The scaffold
  writes files and stops: `pnpm install` and `api-v1`'s `gdoc` are printed as the project's
  first commands.

  There is no `init` subcommand — installing the layout into a server you already have is a
  refactor the CLI cannot do without guessing at someone else's entry file.

  The old scaffold is not part of this repository; `2.2.6` was its last release, and this
  changelog continues from there.

- 0f3fd92: Move the api directory and URL prefix into the config, and fix the artifact names

  The api directory no longer has to be spelled in seven places. `tealina.config` supplies it:

  ```ts
  export default defineConfig({
    apiDir: "src/api",
    apiBaseURL: "/api/v1",
  });
  ```

  Every command reads it, so none takes a directory argument: `tealina create post/order`,
  `tealina delete post/order`, `tealina align`, `tealina gdoc`, `tealina gtype`. Both fields are
  required — `mergeInlineOptions` rejects a config without them — and neither is derivable from
  the other.

  The public artifacts keep fixed names regardless of `apiDir`: `types/api.d.ts`,
  `docs/api.json`, and `exports["./api"]`. Moving the directory therefore changes route
  discovery and handler imports, not what a frontend imports. `convertToOpenApiJson` takes the
  configured `apiBaseURL`, also handed to custom outputs as `GdocContext.baseURL`.

  `exclude` takes globs relative to `apiDir` (`['_shared/**', '**/*.test.ts']`), and
  `handlerImport: 'core/handler'` points generated stubs at a contract in another package; the
  default is still `./handler`.

  `create-tealina`'s templates are written for this release. Projects generated by an earlier
  version need the two required config fields before the new CLI can build them.

- 0f3fd92: Let the host own the documentation page, one source per mounted version

  `mount` in an api package now publishes only its own document json, at
  `${API_BASE_URL}/_doc/api.json`, and returns a `docSource` — the name, base URL and json URL
  the page needs. The `server` package owns the single page: `src/doc.ts` collects the sources
  from every mounted version, renders `assembleHTML` once, and serves the page and its assets
  under `/api-doc`. Adding `api-v2` therefore adds a selector entry instead of competing for
  the page's prefix.

  `version.js` no longer carries `VDOC_BASENAME`: `API_VERSION` names the version and
  `API_BASE_URL` derives from it. `@tealina/doc-ui` exports the `TealinaVdocSource` type, so a
  version package can type what it returns without importing the page configuration.

### Minor Changes

- 0f3fd92: Gather the access module into `src/access/`

  In `core`, `src/access.ts` is `src/access/index.ts` and `src/middlewares/auth/verifyToken.ts`
  is `src/access/verifyToken.ts` — the two files answer one question, is this route public or
  guarded, and `verifyToken` is imported only by `access/index`, so `src/middlewares/auth/` is
  gone.

  A handler imports `'core/access'` instead of `'../../../access.js'`. `core` is a workspace
  package with its own `exports` map, so the specifier is the same at any depth, in any api
  tree, on any framework.

- 0f3fd92: Scaffold the api directory as `src/api`

  The route tree lives in a package whose name already says the version (`backend/api-v1`), so
  the directory no longer repeats it: the route table is `src/api/get/health.ts`. The URL is
  unaffected — `API_BASE_URL` in `version.js` still mounts these routes at `/api/v1`.

  Everything derived from the name moves with it: the six templates' `create` / `gdoc` /
  `align` scripts, every handler's import depth, the README layout tree, and the config's
  `generateFn`, which is handed a directory instead of a depth.

  **Upgrade `tealina` with this.** The generated stub reads `TemplateContext.fileDir`, which
  the previous major does not send, so `align` against an older CLI writes `undefined` in place
  of a path. A project already under `src/api-v1` needs no rename, but does need the config
  change that major describes.

- 0f3fd92: Add `--web`: a minimal frontend that reads the API types instead of restating them

  Off by default. With it, a Vite project lands in `packages/web` beside `backend/`, with no
  framework: no React, no router, no UI library.

  The package is two source files, because what it demonstrates is the client:

  ```ts
  import { createFetchClient } from "@tealina/client";
  import type { ApiTypesForClient } from "api-v1/api";

  export const req = createFetchClient<ApiTypesForClient, RequestInit>(
    requester
  );
  ```

  One `workspace:*` dependency and one `import type`: `api-v1`'s `exports["./api"]` entry is the
  whole mechanism — no code generation, no `tsconfig` paths, no build step. Rename a field in a
  handler and the frontend stops compiling; `test/e2e.test.ts` asserts exactly that, install and
  build included.

  The page calls `GET /health` because the backend ships that route; it is a placeholder for
  the typed `req`, not the markup. `--web` also adds the package to the workspace, which is why
  the root scripts are written as `pnpm -r …`.

- 0f3fd92: A minimal tealina scaffold: no database, no Prisma, three backend workspace packages
  (`core`, `api-v1`, `server`) instead of four. There is no frontend by default — the contract
  is published through `api-v1`'s `exports["./api"]`, so the types are ready for whatever client
  you bring. `--web` writes a minimal Vite one.

  The core idea is unchanged: the directory tree is the route table, and each handler's type
  annotation is the single source of truth that routes, API docs and frontend types derive from.

  Three demo endpoints ship: `GET /health` and `POST /login` (public), `POST /article`
  (authenticated, with a typed body and response). Endpoints require a token by default; one
  becomes public by ending its file in `openApi(handler)` instead of `authedApi(handler)`, so
  the guard lives with the endpoint rather than in a path table. On express and koa the pair is
  also a type check: the guard reads `res.locals.userId`, and `openApi` refuses a handler
  declared `AuthedHandler`.

  No error handler and no not-found handler ship with it, on any framework. An unknown route
  and a thrown error are answered by the framework's own default — express's `finalhandler`,
  koa's `ctx.onerror` — so shaping those responses stays the application's policy. The demo
  handlers answer for themselves: `verifyToken` writes the 401 body directly.

- 0f3fd92: The scaffold writes files and stops

  `--no-install` is gone because there is no longer an install to skip. `create` never runs
  `pnpm install` or `gdoc`; it prints them, with `pnpm dev`, as the project's first commands.
  Installing into a directory the same command may have just emptied, with a package manager
  guessed from the user agent, was doing the risky part invisibly.

  A non-interactive run is a project name plus `--template <fw>`.

- 0f3fd92: Ship an `AGENTS.md` with the scaffold

  The scaffold writes an `AGENTS.md` into `backend/api-v1` and a short root one pointing at it.
  It states what an agent cannot infer from the code: the directory tree is the route table,
  `src/api/**/index.*` is generated and must not be edited, `openApi` vs `authedApi` decides
  access, payload shapes need a named declaration for the document generator, the contract
  lives in `core`, and `core` must not import `api-v1`'s mount code. It also documents
  `align --check`, `gdoc --check` and `--json`.

  Template `index.*` files carry the generated-file header, so the first rule is visible from
  the file itself.

- 0f3fd92: `--integrate` writes an AI merge playbook

  `pnpm create tealina my-app --integrate` writes `INTEGRATION.md` at the project root: a
  one-time guide for an agent merging the scaffold into an existing repository. It is not
  written otherwise.

  The playbook covers copying only `core` and `api-v1` and mounting them on the destination's
  own Express/Fastify/Koa app, or moving all three backend packages into an existing monorepo.
  It names what the copied code cannot tell an agent: the `handlerImport` and generator-stub
  literals that carry package names (miss them and the next `create` writes a broken import),
  why `core` and `api-v1` must be built before the host imports `dist/`, why `src/api/**/index.*`
  and `docs/api.json` are regenerated rather than merged, and how to verify with `align --check`
  and `gdoc --check`.

  The Chinese guide is at `/guide/integration`, and the CLI reference lists the flag.

- 0f3fd92: Scaffold projects with Vite+ formatting and linting

  The generated workspace installs `vite-plus` and ships a root `vite.config.ts`, so a fresh
  project has `pnpm check` (`vp check`) from the first commit: Oxfmt formats, Oxlint lints, and
  the type checker runs over the same sources. `pnpm fmt` and `pnpm lint` run one half alone.

  The formatter matches the template's existing style — single quotes, no semicolons, 80
  columns — so `pnpm check` is clean before anything is edited; generated route barrels are
  excluded because `align` owns their formatting.

  `packages/web` runs through `vp dev` / `vp build` / `vp preview`, and `vite` resolves to the
  copy Vite+ bundles through the workspace catalog and override.

### Patch Changes

- 0f3fd92: Spell the template's api calls without the leading slash

  The generated barrel keys a route by its logical path, so the scaffold's pages and README
  follow `req.get('health')`, `req.post('login')` and `TakeBody<'post', 'article'>` instead of
  `/health`. The route table a fresh project starts with — `'health'`, `'login'`, `'article'` —
  carried the slash until now, and a scaffold is where the spelling is learned.

- 0f3fd92: Build with tsdown instead of unbuild

  `build.config.ts` is gone; `dist/index.mjs` is packed by tsdown through the `pack` block in
  the existing `vite.config.ts`. Still one file, still minified, still at the path `index.js`
  and the root `cproj` script point at.

  `inlineDependencies: true` and the `prompts` alias are not carried over — neither did
  anything: unbuild externals every `dependencies` entry before consulting `inlineDependencies`,
  so `chalk`, `minimist` and `prompts` have always been plain imports for the consumer to
  install, and tsdown's default does the same.

- 0f3fd92: TypeScript is the only scaffold language

  There is one scaffold per framework, written in TypeScript.

  Handlers can also be `.js`: enable `allowJs` in every backend package's `tsconfig.json` and
  `tsconfig.build.json` — the host compiles `api-v1`'s source through its `types` entry — add
  `checkJs` and `src/**/*.js` where the handlers live, and set `sourceExt: '.js'` in
  `tealina.config.ts`. `create` then writes a JSDoc stub and `align` names its barrels
  `index.js`, while `.ts` handlers keep compiling beside them. The package README has the full
  recipe.

- 0f3fd92: Require pnpm 12.x in generated projects

  The generated `package.json` declares `engines.pnpm: ">=12 <13"`, and the project ships a
  `.nvmrc` defaulting to Node 24. `engines.node` still says `>=22`, so Node 22 remains
  supported.

- 0f3fd92: Require Node 22

  `vite-plus-core`'s tsdown calls `Promise.withResolvers`, which Node 20 lacks, so the build
  failed on the floor the packages claimed. `engines.node` is `>=22`, the Node-side `target` is
  `node22`, and `@types/node` is `^22`; CI and `.nvmrc` run the default Node 24.

  Node 20 is no longer supported. Nothing in the published API changed.

- 0f3fd92: Scaffolds pin Vite+ 1.3.0

  The generated `pnpm-workspace.yaml` catalogs `vite-plus` 1.3.0 and aliases `vite` to the
  matching `@voidzero-dev/vite-plus-core`, so a new project installs the current toolchain and
  still resolves a single copy of Vite. The catalog is the scaffold's own pin; upgrading the
  global `vp` does not change it.

- 0f3fd92: Give `types/handler.d.ts` four sections, ordered by what depends on what

  The file had its private machinery interleaved with the names users write — `EmptyObj`
  between two private aliases, `HandlerAlias` wedged between `HTTPMethods` and `OpenHandler`. It
  now reads top to bottom as a dependency chain: the shapes everything is built on, the handler
  declarations, then the projections.

  No type changed, and the contract layer still compiles with `skipLibCheck` off and no unused
  locals.

- 0f3fd92: Scaffold against TypeScript 6

  Every template's `typescript` moves from `~5.8.3` to `~6.0.3`. This is not incidental: `gdoc`
  drives the compiler API, so it is the compiler a generated project is actually checked by.

  TypeScript 6 also changes `types` from "load every `@types/*` in scope" to "load nothing
  unless named". The two shared configs therefore spell out `"types": ["node"]` —
  `src/config/env.ts` reads `process.env` and calls `process.loadEnvFile()`, and without the
  entry every generated project fails `pnpm build` with `Cannot find name 'process'`.

- 0f3fd92: Add a `tealina/utility-types` subpath, and let the scaffold take its types from there

  `tealina` already depended on `@tealina/utility-types`; it now hands those types to consumers
  from a types-only subpath — nothing to import at runtime, and the `exports` entry carries only
  a `types` condition.

  That lets a generated project drop a dependency: the contract layer (`types/handler.d.ts` and
  each framework's `types/alias.d.ts`) imported `@tealina/utility-types` directly, so every
  generated `server` package installed it a second time. Those imports name
  `tealina/utility-types` now, and the dependency is gone from all six template manifests.

  A subpath rather than the main entry on purpose: `tealina`'s root declaration re-exports
  `openapi-types` and reaches its own source through extensionless relative imports, which
  would tie the scaffold's compile to a build having run.
