# AGENTS.md

The backend is three packages under `backend/`, and the dependency direction is one way:

```
core  ->  api-v1  ->  server
```

- `core/types/` is the contract layer. `core/src/access/` is the guard.
- `api-v1/src/api/` is the route table. Each handler's type annotation is the source of
  truth for the router, `api-v1/docs/api.json` and `api-v1/types/api.d.ts`.
- `server/src/` is host glue: it calls `mount(app)` from `api-v1/mount` and adds static
  assets. It holds no routes.

Read `backend/api-v1/AGENTS.md` before changing anything under `api-v1/src/api/` or
`api-v1/types/`.

From the workspace root:

- `pnpm -F api-v1 <script>` for `create`, `align`, `gdoc`, `dev`, `build`
- `pnpm -F core <script>` for `dev`, `build`
- `pnpm -F server <script>` for `dev`, `build`, `start`

Never edit `src/api/*/index.*` by hand — they are generated by `align`.

If the project was scaffolded with `--web`, `packages/web/src/api/client.ts`
(`client.js` in `--js` mode) reads the handlers through `api-v1/api`. Renaming a field in a
handler is expected to break the frontend's type check — that is the point, not a bug.
