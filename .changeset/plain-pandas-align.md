Move the api directory and URL prefix into the config, and fix the artifact names

The api directory no longer has to be spelled in seven places. `tealina.config` now supplies

```ts
export default defineConfig({
  apiDir: 'src/api',
  apiBaseURL: '/api/v1',
})
```

and every command reads it, so the commands take no directory argument:

```bash
tealina create post/order   # was: tealina src/api post/order
tealina delete post/order
tealina align               # was: tealina src/api -a
tealina gdoc
tealina gtype
```

Both fields are required; `mergeInlineOptions` rejects a config without them. They cannot be
defaulted, because `apiBaseURL` is a deployment choice and `apiDir` is where the route tree
is — neither is derivable from the other.

The public artifacts keep fixed names regardless of `apiDir`:

- the type file is `types/api.d.ts` (was `types/<api-dir>.d.ts`)
- the document is `docs/api.json` (was `docs/<api-dir>.json`)
- the package export is `exports["./api"]` (was `exports["./api/<api-dir>"]`)

So moving or renaming the directory changes route discovery and the handlers' relative
imports, not anything a frontend imports. `convertToOpenApiJson` already took the prefix; it
is now the configured `apiBaseURL`, also handed to custom outputs through
`GdocContext.baseURL`.

`exclude` takes globs relative to `apiDir`, so files that are not routes can live in the
tree:

```ts
exclude: ['_shared/**', '**/*.test.ts']
```

A package that keeps its contract in another workspace package can point the generated
stubs at it:

```ts
handlerImport: 'core/handler'
```

The default is still `./handler`, so a project with the contract layer inside its own
package is unchanged.

`create-tealina`'s templates are written for this release: their `tealina.config` declares
`apiDir`, `apiBaseURL` and `handlerImport`, their scripts are argument-less (`tealina
create`, `tealina align`, `tealina gdoc`), and they ship `types/api.d.ts` behind
`exports["./api"]`. Projects generated by an earlier version need the two required config
fields before the new CLI can build them.
